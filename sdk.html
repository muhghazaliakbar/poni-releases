Build a Poni plugin

A plugin is one folder with a manifest.json and a main.js. You write plain JavaScript that returns a layout of components, and Poni draws it in the notch with a native macOS look. No Xcode, build step or npm needed.

Get started

  1. Install Poni and open it once.
  2. Download the plugin template, then unzip the folder into ~/Library/Application Support/Poni/Plugins/. In Finder, choose Go → Go to Folder and paste that path.
  3. Your plugin appears as a new tab right away. Edit main.js, save, and the notch reloads the plugin on the spot.

console.log output, JavaScript errors and other warnings appear in Settings, on your plugin's page, under Console. If manifest.json can't be read, the plugin is listed under Failed to load in the Settings sidebar, with the reason.

What's in the template:

hello/
  manifest.json   the plugin's identity, icon, permissions and settings
  main.js         the plugin's code

manifest.json

{
  "id": "com.yourname.hello",
  "name": "Hello",
  "version": "1.0.0",
  "author": "Your Name",
  "description": "One sentence about what this plugin does.",
  "symbol": "lucide:hand",
  "permissions": ["network"],
  "refreshInterval": 1,
  "order": 50
}
FieldMeaning
idRequired. Unique, lowercase, in reverse-domain form such as com.yourname.hello. The app.useponi. prefix is reserved for official plugins.
nameRequired. The name shown on the tab and in Settings.
versionSuch as 1.2.0. The gallery uses it to offer updates.
author, descriptionShown in the gallery and in Settings.
symbolThe tab icon: lucide:<name> from Lucide, or an SF Symbols name.
permissionsThe permissions the plugin needs; see Permissions.
refreshIntervalSeconds between automatic render() calls. Default 1, minimum 0.25.
orderTab order; lower numbers come first. Users can still rearrange tabs.
mainThe code file's name. Default main.js.
settingsA list of settings; Poni builds the form for you. See below.
localesOptional. Translations of the manifest's text, per language; see Languages.

Settings

List your settings in the manifest. Poni shows the form in the Settings window, saves the values, and adds a button to restore the defaults.

"settings": [
  { "key": "city", "type": "text", "label": "City", "default": "Jakarta", "placeholder": "Jakarta" },
  { "key": "minutes", "type": "number", "label": "Duration", "default": 25,
    "min": 5, "max": 120, "step": 5, "help": "In minutes" },
  { "key": "lyrics", "type": "toggle", "label": "Show lyrics", "default": true },
  { "key": "unit", "type": "select", "label": "Unit", "default": "c",
    "options": [{ "value": "c", "label": "Celsius" }, { "value": "f", "label": "Fahrenheit" }] }
]

Available types: text, number, toggle and select. Read a value with notch.settings.get('city'), or all of them at once with notch.settings.all(). When the user changes a value, Poni calls onSettingsChanged(key, value) and then render().

Languages

Poni is available in English (the default) and Indonesian. Write the manifest's text (name, description, and each setting's label, help, placeholder and option labels) in English, then add translations under locales.id. Anything you don't translate falls back to the English text.

"locales": {
  "id": {
    "name": "Catatan",
    "description": "Catatan singkat di notch.",
    "settings": {
      "showStats": { "label": "Tampilkan grafik 7 hari" },
      "unit": { "label": "Satuan", "options": { "c": "Celsius", "f": "Fahrenheit" } }
    }
  }
}

Keys under settings are setting keys; options maps each option's value to its label.

In main.js, notch.locale holds the app's current language: "en" or "id". It changes when the user switches languages, and render() runs again afterwards, so build your strings inside render(), not when the plugin loads.

var TEXT = {
  en: { title: 'Hello!' },
  id: { title: 'Halo!' }
};

function render() {
  var t = TEXT[notch.locale] || TEXT.en;
  return ui.text(t.title, { style: 'title' });
}

Functions in main.js

Define the functions you need. All of them are optional except render.

FunctionWhen it's called
init()Once, when the plugin loads.
render()Every refreshInterval, and after an action, timer or fetch. Return a layout of ui.* components.
compact()Along with render(). Return { symbol, text, color, wide, image, equalizer } to show next to the closed notch, or null. wide: true makes room for longer text, image shows a small image (such as album art) instead of a symbol, and equalizer: true adds animated equalizer bars.
onAction(action, value)A button was clicked, or a text field was submitted with Return.
onSettingsChanged(key, value)A setting changed. key is null when all settings were reset to their defaults.

UI components

Each ui.* function returns a plain object, so you can combine them however you like.

ui.vstack(children, { spacing, align, padding, paddingX, paddingY, width, background, radius, fill, highlight, stagger })
ui.hstack(children, { spacing, align, padding, width, background, fill, highlight, stagger })
ui.text(text, { style, weight, color, lines, width, align })
ui.ring(value, { size, color, label })        // progress ring (as in Focus)
ui.bars(values, { labels, color, height, highlight })  // small bar chart
ui.symbol(name, { size, color, fill, animation })  // name: 'lucide:music-2' or an SF Symbol
ui.weatherGlyph(condition, { size })           // animated sun and clouds
ui.button(label, action, { symbol, fill, style: 'primary' | 'plain', color, labelColor, compact })
ui.progress(value, { color, height })         // value from 0 to 1
ui.row(label, value, { symbol, highlight, color })
ui.input(placeholder, action, { value })
ui.image(url, { size, radius, placeholder, playing })  // playing: shimmer while playing
ui.camera({ height, radius, mirrored })  // live camera preview; needs "camera". On only while visible
ui.spacer()
ui.divider()
style on text
largeTitle (34), title (17 bold), headline (15 semibold), body (15), callout (14), caption (13), footnote (12), and the monospaced-digit versions mono, monoFootnote, monoHeadline and monoTitle, set in Onest and JetBrains Mono like this page. Text made of numbers (clocks, countdowns, prices) rolls when it changes, like the system clock.
align on vstack
leading, center, trailing.
Colors
primary, secondary, tertiary, accent, blue, green, red, orange, yellow, purple, pink, teal, mint, amber, rose, white/55 (white at 55%), or a hex value #RRGGBB.
Icons
Use lucide:<name> for Lucide icons (as on this page) or an SF Symbol name. fill: true fills the icon. animation: spin, drift (sways), pulse or bob (moves up and down). This also applies to symbol in the manifest, buttons, and compact().
stagger: true
A stack's children animate in one after another when the page opens: rows slide in from the left in a vstack, cards rise from below in an hstack.
background and fill
background adds a subtle colored box with rounded corners; fill: true stretches the stack to the notch's full width.

Permissions

A plugin can only use the APIs whose permissions are listed in permissions and approved by the user.

  • Plugins from the gallery get their permissions when the user approves the install.
  • Plugins you install yourself ask the first time they use a permission. While the dialog is open, calls return null or false; the plugin redraws once the user answers.
  • Users can grant or revoke permissions at any time in Settings, on the plugin's page.
  • APIs whose permission isn't listed don't run: notch.fetch returns an error naming the missing permission, and other APIs return null.

Options: network, media, notifications, clipboard, calendar, system, ai-usage, camera (for ui.camera()), reminders.

Limits

  • Each plugin runs in its own JavaScriptCore context and can't read other plugins' variables.
  • There's no DOM, require, import or browser fetch; use notch.fetch instead.
  • Each call into a plugin is limited to half a second. Longer calls are stopped, and three in one minute pause the plugin until you save a fix.
  • Keep data that needs to last in notch.storage. Ordinary variables are lost when the plugin reloads.

Examples

A counter with wings

var count = notch.storage.get('count') || 0;

function render() {
  return ui.vstack([
    ui.text(count + ' glasses of water today', { style: 'title' }),
    ui.hstack([
      ui.button('Drink', 'add', { symbol: 'lucide:droplet', style: 'primary' }),
      ui.button('Reset', 'reset')
    ])
  ]);
}

function compact() {
  return count ? { symbol: 'lucide:droplet', text: count + ' glasses', color: 'blue' } : null;
}

function onAction(action) {
  count = action === 'add' ? count + 1 : 0;
  notch.storage.set('count', count);
}

Data from the internet

Needs "permissions": ["network"]. Fetch data when the plugin loads and every 10 minutes; render() only draws what's already there.

var rate = null, error = null;

function load() {
  notch.fetchJSON('https://open.er-api.com/v6/latest/USD', function (json, err) {
    error = err;
    if (json) rate = json.rates.EUR;
  });
}

function init() {
  load();
  setInterval(load, 10 * 60 * 1000);
}

function render() {
  if (error) return ui.text('Couldn’t load: ' + error, { color: 'red' });
  if (!rate) return ui.text('Loading rate…', { style: 'caption' });
  return ui.row('1 USD', '€' + rate.toFixed(2), { symbol: 'lucide:circle-dollar-sign' });
}

Submit to the gallery

Every Poni user can install plugins from the gallery with one click. The gallery list is signed, so each plugin is reviewed before it's added.

  1. Check your plugin: id and version are set correctly, the SF Symbol icon exists, every API you use has its permission, you don't ask for permissions you don't use, and the Console shows no errors.
  2. Upload the plugin folder to a public repository, or as a zip.
  3. Open an issue with a link to the plugin, what it does, and why it needs its permissions. Once it's reviewed, the plugin is added to the gallery. For updates, submit the new version with a higher version; users get an Update button in the gallery.
